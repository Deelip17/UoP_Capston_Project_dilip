## Challenges and resolutions (Part A)

| Date | Challenge | How it was resolved |
|---|---|---|
| 2026-11-14 | The domain model class `TestCase` triggered pytest collection warnings because its name matches the test-class pattern | Added a class variable `__test__: ClassVar[bool] = False` on the pydantic model so pytest skips it without renaming the domain concept |
| 2026-11-14 | Ruff rule UP042 rejected `class RiskLevel(str, Enum)` on Python 3.12 | Switched both enums to `enum.StrEnum` which is the Python 3.11+ idiom |
| 2026-11-14 | The pipeline must complete offline and deterministically (FR-36) but the mock provider returned only a generic JSON stub that fails the analyzer's schema | Gave the mock provider per-component responders; the analyzer registers a rule-based extractor that returns schema-valid JSON, and the analyzer's own keyword risk rules are what the tests exercise |
| 2026-11-14 | Requirement text is untrusted and shares the prompt with instructions (NFR-13) | Fixed delimiters plus an instruction hierarchy in a versioned prompt, injection screening that rejects before any LLM call, masking before the call, and schema validation of the reply with one re-ask |
| 2026-11-14 | `TestCase` had no field for model or prompt version although NFR-30 requires every AI artefact to carry both | Added required `model` and `prompt_version` to `TestCase`, and to the new `TestScenario`; updated the slice 1 model tests and added tests that empty values are rejected |
| 2026-11-14 | A Markdown export can only round-trip without loss if no field contains a line break | The generator normalises every title, step and expected result to one line before storing it; export tests cover awkward content (quotes, commas, colons, a leading dash, Unicode) in all three formats |
| 2026-11-14 | FR-08 forbids real personal data but a model may still suggest realistic-looking values | Each suggested value is masked-checked; reserved example and test domains are allowed, anything else is replaced by a rule-based synthetic value and counted in the run summary |
| 2026-11-14 | Generated code is untrusted and runs on the user machine, yet a model should not be asked to write free-form code | The model returns a structured plan only; Python templates write the code. Names are restricted to simple identifiers by the schema, and an AST allow-list (imports, builtins, attributes, URL hosts, secrets) validates every generated file before it is saved, as defence in depth |
| 2026-11-14 | FR-12 and FR-13 ask for scripts that execute against a sample application, but there is no Execution Engine, browser run or sample app yet | Verified what can be verified now: every file parses, compiles and passes validation, and the generated test function runs against fake Playwright and Selenium drivers where only the second locator strategy exists. Real-browser execution is left to the Execution Engine slice |
| 2026-11-14 | The generated evidence files tripped the ruff line-length rule in the lint job | Excluded the `evidence` folder from ruff because it holds generated output, not source |
| 2026-11-14 | Healing has to be testable without a browser, yet the ladder must evaluate stored locators | Parse the DOM snapshot with the standard library and evaluate the supported CSS and XPath subset against it; a selector outside the subset returns None and is skipped rather than guessed |
| 2026-11-14 | Healing must not hide real defects | Classification decides first and by exception type (an assertion is a defect even if its message mentions a missing element); only locator failures enter the ladder, and the E07 log shows an assertion failure left alone |
| 2026-11-14 | Similarity alone accepted a wrong element: in the look-alike fixture the Cancel order button scored 0.67, above the 0.6 threshold | Added a separate validation step (role, text, context, action fit) that rejects it, so the step still fails; the two checks are deliberately independent layers |
| 2026-11-14 | A stored fallback such as text=Sign in can match two elements, so proposing it would heal to the wrong one | A proposed locator must resolve to exactly the chosen element; otherwise a stable unique locator (id, test attribute, classes, type, text) is derived, or the candidate is rejected |
| 2026-11-14 | Similarity needs a description of the original element, but the locator record holds only strategies | Use a baseline signature from the last good snapshot when the Execution Engine supplies one, otherwise derive a partial signature from the locator; a test shows the baseline is what lets the all-changed fixture heal |
| 2026-11-14 | The LLM rung sends page content to a model and page content is untrusted | Send only the top candidates, masked, with injection-like lines removed, delimited as untrusted data, schema-checked, validated like any other candidate, off by default and capped by the gateway |
